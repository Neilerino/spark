## 1. Compare independently constructed tuples by their fields

Start with a `tuple_value_equality` driver fixture under `run-pass/collections/`. Call `point(x, y): Tup[Int, Int]` three times to construct `a = (1, 2)`, `b = (1, 2)`, and `c = (1, 3)`. In `spark_driver/tests/e2e.rs`, use `run_spark_with_args` to assert zero exit and exact output with default optimization and `--no-opt`.

| Expression | Expected | Baseline in both modes |
| --- | --- | --- |
| `a == b` | true | false |
| `a != b` | false | true |
| `a == c` | false | false |
| `a != c` | true | true |

Extend the fixture after the tracer passes. Cover first and last field differences, nested tuples, mixed integer widths and padding, and equal/different String fields constructed through independent interpolation. Include temporary operands and comparisons in a condition. For Float fields, confirm that positive and negative zero compare equal and NaN follows Spark scalar equality. A native reference-count fixture should cover named inputs and fresh tuple temporaries containing owned String fields. Confirm that a comparison neither leaks a retain nor frees an input that is still live.

- In `spark_types/src/check_expr.rs::check_binary_op`, give tuple equality an explicit representation-compatible rule. Accept equal arity and matching field types after representation-preserving mutable normalization, recursively accepting integer, float, Bool, Char, Byte, String and nested tuple fields. Keep existing operand auto-deref conventions. Diagnose mismatches and unsupported fields, including collections, references, callables, tagged values, and user-defined structs. Custom comparison remains available for top-level operands through the existing protocols. Reject tuple relational operators because this ticket defines equality only. Preserve unrelated scalar paths.
- Keep HIR's existing binary operators and MIR's `Rvalue::BinaryOp`. Use a shared typed slot comparator in Cranelift. Dispatch before the generic integer path, which currently sees aggregate addresses. Walk fields at `LayoutCache::tuple_field_offset` with exact-width loads, recurse through nested tuple slots, and compare String contents through the existing runtime equality function. Compute `!=` by negating structural equality. Skip tuple padding entirely. Keep this comparator suitable for the slot ABI used in slice 3.
- Treat operands as borrowed. Cranelift's owning `emit_operand(Copy)` retains managed values, so borrow existing places with `emit_place_read` or `emit_place_addr` as appropriate. Evaluate each operand once, left to right. Stage the left value before evaluating a right-hand expression that could change its binding. A borrowed address to the original binding would observe that change. Materialize managed operands, including String literals, in scoped MIR places before borrowed codegen reads. Release staged and fresh owners on normal and early exits. Keep named and already-registered owners live, and reuse the staged slots for field reads. Add driver cases for once-only evaluation, a right-hand expression that changes the left binding, and cleanup when the right-hand expression exits early.

## 2. Order Strings lexicographically by contents

Add a `string_value_ordering` driver fixture using independent runtime interpolation with the same suffix twice. The baseline reports equality and also a strict ordering relation. Test all six operators in both modes. Equal inputs satisfy both inclusive relations and neither strict relation. For unequal inputs cover reversed arguments, ASCII with an opposing length order, prefixes, UTF-8, and empty Strings. Include a typed `Ref[String]` case through the current automatic dereference path and run a native ownership probe for named and temporary comparison operands.

- Dispatch String comparisons before generic integer lowering in `spark_codegen/src/cranelift/emit_rvalue.rs`. Use one internal signed three-way result for relational predicates and compare it against zero with signed conditions. Keep the equality ABI and use the same byte semantics. Require String on both sides after supported auto-deref and diagnose accepted-by-compatibility operands with different layouts.
- Implement the runtime comparator using the existing empty-safe `spark_str_bytes` helper. Match String list sorting with unsigned UTF-8 bytes and normal prefix rules. Define a fixed `-1/0/1` ABI through `spark_abi` and Cranelift `RuntimeStubs`. The ABI borrows two String object pointers. Descriptor callbacks receive pointers to collection slots instead.
- Reuse the comparison ownership path from slice 1 for String operators. Check that a zero comparison result agrees with content equality. Keep String hash and equality descriptors consistent. Preserve their same-pointer and null-slot handling, but use the empty-safe byte view for distinct valid objects. Baseline independently allocated empty keys abort in `value.rs::libc_memcmp` because their null data pointers are used to make slices of length zero. Cover independent empty and nonempty equal keys in Map lookup and Set membership here, with runtime tests for the comparator.

## 3. Use value equality for tuple list membership and enforce the hash-key boundary

Start with a `tuple_list_contains` driver fixture for a `List[Tup[Int, Int]]` containing `a`. Assert `contains(b)` succeeds and `contains(c)` fails with independent probes. Add mixed-width and String-containing tuples. Include an empty list, a temporary probe and receiver, and an ownership fixture with a named String inside the probe tuple. Run both modes.

- A correct `contains` needs both the correct address and the correct equality. In `spark_codegen/src/cranelift/emit_term.rs`, use a borrowed address for a probe place, generalizing the existing Set helper only to representations proven valid by the checker. An aggregate operand already has its slot address. Avoid spilling that address into another slot and avoid an owning copy when the runtime borrows the probe. If constant operands reach this path, materialize their valid scalar representation and account for ownership. Reuse MIR's scoped receiver and argument cleanup for temporary List and Map inputs.
- Reuse the slice 1 comparator in generated per-tuple equality callbacks with the runtime's `ElemEqFn` two-slot-pointer and i8-result ABI. Deduplicate by concrete tuple TypeId and bind the callback through `emit_value_desc` for matching list element types. Follow existing element glue discovery and verify nested collection paths where descriptors are built. An aggregate address fix alone leaves `__spark_list_contains` using raw byte comparison, including padding and String pointer identity. Keep existing scalar callback and drop/retain behavior. Require the same supported tuple field comparator and exact slot shape in the checker. Keep custom list `Equatable` and `Comparable` dispatch in NEI-121.
- Keep Map and Set keys restricted to existing integer and String slots. Test lookup, `contains`, replacement or deduplication, and removal by an independently constructed equal key. Include a narrow integer and the empty and nonempty String cases. Integer slot equality and hashing already agree on the same exact-width representation. String callbacks already hash contents. Keep the current hash algorithm and verify that independent equal keys still reach the same entry. Keep tuple hashing, new key types, and general collection equality outside this ticket.
- Close unchecked key paths with the existing `is_supported_hash_slot` policy. Nonempty literals reject tuple keys and typed empty Set literals diagnose, but a typed empty `Map[Tup[Int, Int], Int]` compiles and runs. Check explicitly concrete Map/Set type arguments and concrete generic instantiations before codegen. Defer unresolved generic parameters until their concrete type is known. Use a focused diagnostic for unsupported types at the point where a concrete layout is required. Ensure inferred literals, empty construction, and key operations share the same rule. Add compile-fail cases for unsupported concrete keys in an empty Map and in an operation, plus a supported generic instantiation if that path changes. Require a type diagnostic.
